- **Input.** `build_report(rows, now, days=7, lead_times=None, tz_name="America/Detroit")`. `rows` are `(visited_at, visitor_id, path, referrer, bot)` exactly as `site_visits` stores them (`visited_at` is UTC text `YYYY-MM-DD HH:MM:SS`; `referrer` a bare host or None; `bot` None for a person, else `self` / `health` / `crawler` / `probe` / `preview` / `preview:<App>`, see `visit_bot_flag`, pipeline_utils.py:2726). `lead_times` is a list of UTC timestamp strings of contact-form submissions, or `None` when they could not be read. `days` is clamped to 1-90 (the retention). - **Days.** The window is the last `days` calendar days in `tz_name` ending with today (today is partial, say so in the render). Each row's day is its `visited_at` converted from UTC to `tz_name`; a missing zone database falls back to UTC and sets `tz_fallback: true` (the render then says "days in UTC").
- **A visitor is a visitor-day.** Key = `(local day, visitor_id)`. `visitor_id` is salted per day by design (`visitor_salt_for`, main.py:20438), so the same person on three days is three visitors. The render says so; do not try to link ids.
- **Source of a visitor-day = the referrer of its EARLIEST view that day** (ties: input order). Its pages = the set of pages it viewed at any time that day, landing page included ("viewed", not "went on to": the order is not used). Decision stated in the docstring.
- **Categories, in this order, constants `CATEGORIES` (exactly 10; a test pins `5 <= len <= 10`):** humans: `direct` (no referrer), `linkedin` (host `linkedin.com` or a subdomain; `normalize_referrer_host` already maps `lnkd.in` and the Android app), `search` (google.*, bing.com, duckduckgo.com, search.yahoo.com, yahoo.com, ecosia.org, search.brave.com, baidu.com, yandex.*, kagi.com, startpage.com), `mail_chat` (mail.google.com, com.google.android.gm, outlook.live.com, outlook.office.com, outlook.office365.com, mail.yahoo.com, mail.proton.me, web.whatsapp.com, t.me, web.telegram.org, app.slack.com, slack.com, teams.microsoft.com, discord.com, messenger.com), `other_sites` (any other host); bots: `self` (Kevin), `preview` (link unfurlers, any `preview` / `preview:<App>`), `crawler`, `probe`, `health`. Host lists are constants with the comment "a guess, not a measurement"; a host in none of them lands in `other_sites`, and `other_sites` prints its top 3 hosts so a misfiled one is visible. An unknown `bot` string (not in the list) counts as `crawler`. Path matching ignores query/fragment and trailing slash. Contact form SUBMISSIONS are not pageviews: they come from `lead_times` and are shown as one separate line, never attributed to a source (the lead rows carry no visitor id).
- **Per category result:** `visitors` (visitor-days), `hits` (rows; for bots this is the number that matters and the render shows both), `pages` {column: visitor-days that viewed it}, `per_day` list of visitor-days per window day (oldest first), `top_hosts` [(host, visitor-days)] (max 3; `direct` and bot kinds have none), `apps` for `preview` ({App: hits}). Categories with zero hits are kept in the data and hidden in the render except that a one-line `none: <names>` says which were empty.
- **Render.** `render_report(report)` -> list of message strings (use a 3,500-character chunker like the one in TASK-258 if it exists in `done/`, otherwise write a local `_chunk`; never break inside an HTML tag), at most 3 messages. Layout: header `montelattice.com, last N days (today is partial), days in America/Detroit`; humans section first, then bots; per category two lines: `LinkedIn: 12 visitors · Home 10 · Resume 4 · Job Engine 3 · Docfiler 1 · Other 2` and under it `per day: 0 2 5 1 0 3 1` (for `days > 14` buckets of 7 days ending today, labelled `per week`; the first bucket may be partial and is labelled with its length); then `Contact form submissions: N (cannot be tied to a source)` or `Contact form submissions: unknown (could not be read)` when `lead_times is None` (an unreadable read is never a zero); then the cannot-know block. A window with no rows at all says `No pageviews stored for this window` plus the retention fact, and still prints the cannot-know block.
- **`CANNOT_KNOW`** (constant list, printed verbatim, each one sentence, plain words; Kevin asked for these to be said plainly): (1) `Direct` also holds visits that arrived from your own pages: the stored referrer drops same-site hosts (`record_site_visits` -> `normalize_referrer_host`, main.py:20456), so own-site navigation and a typed address look the same. (2) Direct also holds visits from apps that send no referrer: email apps, most messaging apps, PDFs, and browsers with referrer stripping. (3) Visitors are counted per day: the id changes every day on purpose, so the same person on three days counts three times and a returning visitor cannot be told from a new one. (4) The referrer is only a host: no search words, no LinkedIn post, no email subject. (5) A bot that sends a normal browser identity is counted as a person; a person on an odd browser may be filed as a bot. (6) `Viewed` means opened at some point that day; the order of pages and time spent are not used. (7) Link-preview fetches show that a link was pasted into an app, not that anyone opened it. (8) Contact form submissions carry no visitor id, so they cannot be placed under a source. (9) Nothing older than the retention window exists (90 days by default).
- **Hard rules.** Escape every host, app name and path text with `html.escape`. Never print or store a `visitor_id`. No category count may be "free" of a source: totals across categories equal `visitors_total` (a test pins it).
