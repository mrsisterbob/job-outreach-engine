This is a MEASUREMENT feature. The endpoint shapes it will be pointed at are read off the third-party repo `danielhagever/job-board-apis` README and are UNTESTED by us, so the module must treat a field path as a hypothesis, report when it did not match, and keep enough about the real reply (key NAMES only) that the next step can correct it. No posting text, name, location or link is ever stored in a result, only counts and key names.

Build exactly these public names (TASK-231 calls them):

- `UNFETCHED_SYSTEMS = ("icims", "taleo", "successfactors", "oracle", "workable", "bamboohr", "adp", "ukg")`. A test asserts all eight are keys of `board_system_classifier.VENDOR_MARKERS`, that there are exactly eight, and that none of greenhouse, lever, ashby, smartrecruiters, workday is in it.
- `EndpointSpec` (namedtuple): `system`, `method` ("GET" or "POST" only), `url_template` (uses `{0}`, `{1}` for the parts of a board reference), `body` (a dict or None, for POST), `list_path`, `title_paths`, `location_paths`, `apply_paths`, `source_note`. Each `*_paths` is a tuple of candidate paths, each path a tuple of dict keys / list indexes, so a field with two plausible names is tried in order and the first non-empty value wins. `list_path == ()` means the reply itself is the list of postings. `source_note` is where the shape was read (README heading plus the exact line) and is printed in the report.
- `parse_board_arg(text)` -> `(system, ref)` from `"icims=acme/jobs"`. Raises `ValueError` (with a reason) for: no `=`, a system not in `UNFETCHED_SYSTEMS`, an empty ref, a ref part containing anything outside `[A-Za-z0-9._-]` (this blocks a scheme, `@`, `:`, whitespace, `..` and `?`), or an empty part. Parts are separated by `/`.
- `build_url(spec, ref)` -> the URL with `ref`'s parts filled in. `ValueError` when the number of parts differs from the number of `{n}` placeholders in the template, and when the result is not `https://`.
- `resolve_path(obj, path)` -> the value at the path, or `None` when any step is missing or of the wrong type. Never raises.
- `first_value(obj, paths)` -> `(value, which_index)` for the first candidate path giving a non-empty string (strip it; a list of strings counts if the first is non-empty; a dict counts if it has a non-empty `name` / `label` / `text` / `city` string), else `(None, None)`.
- `measure_reply(spec, status, body_text)` -> a plain dict result with exactly these keys: `system`, `outcome`, `http_status`, `parses`, `posting_count`, `with_title`, `with_location`, `with_apply_link`, `with_all_three`, `top_level_keys`, `first_posting_keys`, `source_note`. `outcome` is one of: `"no_answer"` (status `None`), `"http_error"` (status not 200), `"not_json"` (200 but the body does not parse), `"json_no_list"` (parses but `list_path` gives no list), `"ok_empty"` (a list of zero postings; a board with no open roles, not a failure), `"ok"`. `parses` is True only when the body is valid JSON. `posting_count` is `None` unless a list was found. The three `with_*` counts are over EVERY posting in the list, and `with_all_three` over postings that have all three. `top_level_keys` is at most 10 key names of the reply when it is a dict; `first_posting_keys` at most 15 key names of the first posting when it is a dict. A reply whose JSON is a bare string/number, a posting that is not a dict, or a list of mixed types never raises: non-dict postings simply count as having none of the three.
- `no_answer_result(spec, error_text)`, `no_public_endpoint_result(system, reason)` and `not_measured_result(system)` build the same-shaped dict for the three non-reply cases (outcomes `"no_answer"`, `"no_public_endpoint"`, `"not_measured"`); `error_text` is cut to 120 characters and holds the exception CLASS name or a status text, never a URL or body.
- `render_report(results)` -> list of text lines in `UNFETCHED_SYSTEMS` order: one line per system with outcome, HTTP status, parses, posting count and the three counts as `n/N`, then the `source_note`. A system missing from `results` prints as `not measured (no board supplied)`. A final line states in words how many of the eight returned at least one posting that has a title, a location and an apply link, and how many did not answer or have no public endpoint. It must not call anything "working" or "verified"; it states what was measured on one board per system.
